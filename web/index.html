      Threat model
      
Its entire input diet is written by your competitors

      
A crawling agent reads pages authored by people with a financial interest in you ranking worse — and it holds keys to your website. Everything below follows from that.

    


    

      

        Plane 01
        
Analysis

✓ Sees third-party bytes

        
✕ Holds credentials

      

      

        Plane 02
        
Planning

        
Decides what to do. Emits typed actions. The LLM lives here and only here.

        
✕ Sees third-party bytes

        
✕ Holds credentials

      

      

        Plane 03
        
Execution

        
Applies validated actions. Snapshot, apply, re-fetch to verify, record.

        
✕ Sees third-party bytes

        
✓ Holds credentials

      

    

    
No plane both reads attacker-controlled bytes and holds a credential. That separation is structural, not a policy.


    

      

        
01

        
The first-appearance rule

        
No action may contain a URL or domain whose first sighting was inside third-party content. One deterministic rule that kills canonical injection, attacker redirects, hreflang poisoning and disavow attacks — without asking a model to be clever.

      

      

        
02

        
Fail-closed by construction

        
Binds 127.0.0.1:7777. Host-header allowlist, Origin and Sec-Fetch-Site checks, CSRF header, constant-time token compare, CORS stripped. Auth cannot be disabled; binding off-loopback without it throws before the socket opens.

      

      

        
03

        
30 payloads, all blocked

        
Hidden text, Unicode tag blocks, bidi overrides, base64 and HTML-entity payloads, X-AI header injection, off-site canonicals, JSON-LD hijacks. Adding one that gets through is a build failure.

      Questions
      
The ones that actually get asked

    

    

      
Will it break my site?
Every change stores a before-snapshot, then re-fetches the live page to confirm the write landed — and rolls back automatically if it didn't. Dangerous categories (robots.txt, noindex, redirects, canonicals, page deletion) always require a human click and cannot be set to auto. New sites get a 7-day observe-only period where Sean watches and proposes but writes nothing. sean freeze halts everything, everywhere, and survives a restart.

      
Is this going to get me a Google penalty?
The design constraints come from Google's own spam policies, not our caution. Content generation is capped at 2 new pages and 2 refreshes per day per site, because scaled content abuse is defined by scale. Link buying, PBNs, cloaking, hidden text and review gating are refused with no setting to enable them. The edge worker is asserted in CI to never branch on user-agent.

      
What does the LLM actually see?
Narrow judgement calls only, on closed-schema structs — never raw page content, never a credential, and it never calls a write API. It emits typed actions that deterministic code validates against 15 checks before anything is applied. Prioritisation is a published formula, not a model output.

      
Do I need paid API keys?
No. The free stack — Search Console, Analytics, PageSpeed, CrUX, Bing, and Sean's own crawler — covers roughly 90% of capability with zero paid keys. sean audit runs the full 425-check audit with no account and no credentials at all. You supply an LLM key for the writing features; paid data providers are optional and quote their cost before spending.

      
Can it prove it worked?
Sometimes, and it says so when it can't. Every claim carries an evidence tier from A to E, and only tier A — a pre-registered controlled experiment with a matched cohort — is allowed to claim causation. Small sites usually land at tier E, which reads "applied; not measurable at this traffic volume." Tools that promise more than that are the ones people stop trusting.

      
Why AGPL?
Because it's a real OSI-approved licence rather than a source-available substitute. You can self-host, modify and redistribute. The network-use clause is what prevents someone reselling it as a hosted service without contributing back. Commercial features live in a separately-licensed packages/ee/ so the AGPL claim over the core stays clean.
